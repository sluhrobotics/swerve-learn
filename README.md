# Learning Swerve From Scratch

An FRC team training course for building a swerve drive **from scratch to learn how it works**. This is a teaching project, not competition code. Once the team understands the system, we'll switch to an established library (YAGSL, or CTRE's swerve generator) for competition.

Right now this folder holds the **course material**: a documentation website built with [MkDocs](https://www.mkdocs.org/). The robot code (a WPILib Command-Based Java project) gets created in Phase 0 of the course. A runnable reference version lives in [Team-5176/swerve-learn-robot](https://github.com/Team-5176/swerve-learn-robot); clone it next to this folder (see `docs/companion-code.md`).

## Viewing the course

**Option 1: no install.** If the folder has a `site/` directory (zip copies do; git clones don't), open `site/index.html` in a web browser. (The search box may not work when opened as a local file. Everything else does.)

**Option 2: live preview while editing.** Install Python 3, then run:

```bash
pip install mkdocs
```

```bash
mkdocs serve
```

Open http://127.0.0.1:8000. The page reloads every time you save a file in `docs/`.

**Rebuild the static site** after editing (updates the `site/` folder):

```bash
mkdocs build
```

The site uses the built-in `readthedocs` theme, so `mkdocs` is the only package you need.

## The roadmap

| Phase | Topic | Goal |
|---|---|---|
| 0 | Setup | Build and run a Command-Based project in simulation |
| 1 | Geometry and frames | Predict the sign of every value in the robot frame |
| 2 | One swerve module | Make a simulated module track angle and speed |
| 3 | Module optimization | Never rotate a wheel more than 90° |
| 4 | Inverse kinematics | Hand-compute module states for any chassis motion |
| 5 | Four modules + teleop | Drive a simulated robot with a controller |
| 6 | Gyro, field-relative | "Stick up" always means away from the driver |
| 7 | Forward kinematics, odometry | Track where the robot is on the field |
| 8 | Discretization | Remove the "drifting in an arc" skew |
| 9 | Real hardware | Bring up real motors and encoders safely |
| 10 | Tuning | Characterize with SysId and tune gains |
| 11 | Autonomous basics | Drive to a pose automatically |
| 12 | Graduation | Map our code to YAGSL and debug it |

Each phase follows the same pattern: theory first, small testable steps, students write the core math, compare against WPILib with a unit test, then a checkpoint (summary, quiz, real-world failure modes).

## Key conventions

- **Language:** Java, WPILib Command-Based.
- **Coordinate frame:** WPILib standard. +X forward, +Y left, +θ counterclockwise (viewed from above).
- **Module order:** front-left, front-right, back-left, back-right, everywhere.
- **Units:** SI internally (meters, radians, m/s, rad/s), with units in variable names when ambiguous.
- **Not allowed:** YAGSL, the CTRE Tuner X swerve generator, or copied template swerve code (until Phase 12). WPILib math/geometry classes are fine.

The full details are in `CLAUDE.md` and `docs/conventions.md`.

## Setting up on a new computer

1. Unzip the folder anywhere (for example `C:\CODE\swerve-learn`).
2. To view or edit the course, follow **Viewing the course** above.
3. To start Phase 0, install the current WPILib release (VS Code + tools) and AdvantageScope. `docs/phases/phase-00-setup.md` has the steps.
4. **Using Claude Code:** open the folder in Claude Code. It reads `CLAUDE.md` automatically, so it already knows the teaching rules (explain before coding, let students write the math, etc.). Start a session by saying which phase you're on.
5. Or skip the zip and clone the repository from GitHub (`site/` isn't included, so run `mkdocs build` or use `mkdocs serve`).

## Before zipping

- You can leave `site/` out to make the zip smaller. Anyone can rebuild it with `mkdocs build`.
- Once robot code exists, leave out `build/`, `.gradle/` and `bin/`. Gradle regenerates them.
